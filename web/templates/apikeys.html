Keys authenticate calls to managerd's external API. Creating the first key here turns on API-key authentication for every node in the cluster, permanently - once enabled it cannot be turned back off (short of restoring an older raft snapshot), even if every key is later revoked.

{{if not .APIKeys}}

Before you create the first key, read this (issues #75/#80):

The moment the first key exists, API-key authentication is enabled across the Colony. This Comb - the one serving this page - is provisioned for you automatically: its own managerd.json peer_api_key and frontend.json manager_api_key are set to the key you are about to create, with no extra step.

Every OTHER Comb in the Colony needs its own credential too, and the ones that predate automatic peer credential setup need a one-time root-run apiaryctl peer-credential-backfill on the leader and then on each existing member. It installs a limited Operator peer key for background peer operations and restarts managerd; the frontend picks its key up without a restart.

If you install one yourself instead, these are the two files and the two fields:

  • /usr/local/etc/apiary/managerd.json — the peer_api_key field, for this Comb's managerd to call its peers.
  • /usr/local/etc/apiary/frontend.json — the manager_api_key field, for this Comb's frontend to call its own managerd.

User actions from a follower are forwarded to the leader with the caller's authenticated API key over verified peer TLS; do not copy this key to other Combs - each Comb needs a credential of its own, and the backfill command installs a shared Colony peer key rather than a copy of yours. Newly joined Combs receive their own peer key during the approved join flow. If the Colony has no restart-guardrail token yet, provision one on the leader first.
