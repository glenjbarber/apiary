What kind of workload

Step 1 of 5. This answer decides which of the steps below apply, and it is submitted with the form: a VM and a jail have different fields, and Apiary will not quietly ignore one you filled in for the other.

A virtual machine is a bhyve guest with its own disk, vCPUs, memory, install media and firewall. A FreeBSD jail is a process-level jail(8) instance that shares its owning Comb's kernel, CPU, memory, network stack and pf ruleset - which is why most of the steps below simply do not apply to it.

Compute is not available for a jail. A jail shares its owning Comb's kernel and CPU, so it has no vCPU count or memory limit of its own - Apiary's own jail placement carries neither field. Switch the answer in step 1 to a virtual machine to set them.

Compute

Step 4 of 5, virtual machines only. bhyve allocates these to the guest; a jail has neither.

Disk and boot media are not available for a jail. A jail's root is a directory tree populated by a base template or a base archive (step 5), not a disk image: `zfs clone` and bhyve have nothing to attach here. Switch the answer in step 1 to a virtual machine to use them.

Network

Step 5 of 5. Both workload types attach to a managed network here; what differs is what the attachment gives them. A VM always gets its own tap interface on the named network's bridge. A jail by default shares its owning Comb's own network stack (ip4=inherit, unchanged behaviour) and can opt into a dedicated VNET stack instead (ADR-0117).

VNET is a jail option: a VM always gets its own tap interface on the selected network, so there is nothing for it to opt in to.

Initial state is not available for a jail. A jail is created stopped and started from its own lifecycle control afterwards, so Apiary stores no desired state for it at creation.

Firewall rules are not available for a jail. A jail uses its owning Comb's own pf ruleset rather than a per-jail one, so there is nowhere for per-jail rules to go.

Firewall rules

Step 5 of 5, virtual machines only. Optional. With no rules, traffic is allowed. Priority breaks ties when rules overlap - a higher number is evaluated later and wins (pf's own last-match-wins evaluation); leave at 0 if only one rule could ever match a given packet.
