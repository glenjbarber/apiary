What kind of workload

This answer decides which of the panes below apply, and it is submitted with the form: a VM and a jail have different fields, and Apiary will not quietly ignore one you filled in for the other.

A virtual machine is a bhyve guest with its own disk, vCPUs, memory, install media and firewall. A FreeBSD jail is a process-level jail(8) instance that shares its owning Comb's kernel, CPU, memory, network stack and pf ruleset - which is why most of the panes below simply do not apply to it.

Identity

Hostname is the canonical input and may be a full FQDN - a dotted hostname is not a valid resource ID (Apiary allows alphanumerics, - and _, up to 64 characters), so the ID below is derived from it. Edit either derived field to override it.

Compute is not available for a jail. A jail shares its owning Comb's kernel and CPU, so it has no vCPU count or memory limit of its own - Apiary's own jail placement carries neither field. Switch the answer in the Kind pane to a virtual machine to set them.

Compute

Virtual machines only. bhyve allocates these to the guest; a jail has neither.

Disk and boot media are not available for a jail. A jail's root is a directory tree populated by a base template or a base archive below, not a disk image: `zfs clone` and bhyve have nothing to attach here. Switch the answer in the Kind pane to a virtual machine to use them.

Disk and boot media

Virtual machines only. Exactly one of these decides how the VM's disk starts out: a base image copied in, a clone of another VM's snapshot, or a blank disk. Install media can be attached on top of any of them, to install onto a blank or freshly seeded disk.

Network

Both workload types attach to a managed network here; what differs is what the attachment gives them. A VM always gets its own tap interface on the named network's bridge. A jail by default shares its owning Comb's own network stack (ip4=inherit, unchanged behaviour) and can opt into a dedicated VNET stack instead (ADR-0117).

VNET is a jail option: a VM always gets its own tap interface on the selected network, so there is nothing for it to opt in to.

Initial state is not available for a jail. A jail is created stopped and started from its own lifecycle control afterwards, so Apiary stores no desired state for it at creation.

Firewall rules are not available for a jail. A jail uses its owning Comb's own pf ruleset rather than a per-jail one, so there is nowhere for per-jail rules to go.

Firewall rules

Virtual machines only. Optional. With no rules, traffic is allowed. Priority breaks ties when rules overlap - a higher number is evaluated later and wins (pf's own last-match-wins evaluation); leave at 0 if only one rule could ever match a given packet.
