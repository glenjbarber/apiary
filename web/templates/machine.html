Network interface

Which physical interface VLAN tagging and outbound NAT (ADR-0048) use on this node, and which resolver Apiary advertises to Cells. Changes here take effect the next time this node's managerd restarts, not live. Blank NAT uplink means use Uplink. Blank DNS means use the startup flag value, if one was supplied. Interface choices are discovered from this Comb; a saved interface that is no longer present is retained as an unavailable choice so it can be cleared safely.

{{template "nodeconfig_panel" .}}

Resource scope paths

Where this Comb looks for its own existing VM storage, jail images, and installer images. Write-once through this page: changing one of these after real resources already exist under the old value does not move them - it just makes the reconciler stop seeing them, silently orphaning real VMs, jails, or ISOs. Once a value below is set, it can only be changed by editing the underlying rc.conf flag directly and restarting.

Bhyve / VM provisioning

Blank boot ROM disables bhyve provisioning on this node entirely; blank bridge disables VM networking. Disk size and reconcile interval only affect newly created VMs/ticks, never an existing one.

Cloudflare Tunnel exposure

Lets a Cell's own HTTP service be reached at a public hostname through a Cloudflare Tunnel, without opening any inbound port on this Comb - see docs/adr/0063-cloudflare-tunnel-exposure-v1.md in the repository. Set per-Cell on each VM's own detail page, once configured here.

{{if .CloudflareConfigured}}

configured This Comb's managerd has Cloudflare Tunnel exposure enabled.

{{else}}

not configured This Comb's managerd has no Cloudflare Tunnel exposure configured - Cells on this Comb cannot be exposed until it is.

One-time setup per Comb, done by hand (this project never automates it):

  1. The domain's DNS must already be managed by Cloudflare (its nameservers point at Cloudflare).
  2. Install cloudflared on this Comb, then run cloudflared tunnel login and cloudflared tunnel create <comb-name> once - this produces a tunnel id and a credentials JSON file.
  3. Create a Cloudflare API token scoped to Zone:DNS:Edit only (never Tunnel:Edit or account-level) for the zone Apiary will manage CNAME records in, and save it to a file only this host can read.
  4. Fill in the token file's path plus the zone/tunnel id and credentials file path below (or set the matching -cloudflare-* flags directly in rc.conf), then restart apiary_managerd.

Once set, Apiary automatically creates/updates the DNS CNAME record for each exposed Cell - no manual DNS editing per Cell.
