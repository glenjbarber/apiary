Storage and provisioning

Resource scope paths

Where this Comb looks for its own existing VM storage, jail images, and installer images. Write-once through this page: changing one of these after real resources already exist under the old value does not move them - it just makes the reconciler stop seeing them, silently orphaning real VMs, jails, or ISOs. Once a value below is set, it can only be changed by editing it directly in /usr/local/etc/apiary/managerd.json (ADR-0100) and restarting.

Service exposure

Cloudflare Tunnel exposure

Lets a Cell's own HTTP service be reached at a public hostname through a Cloudflare Tunnel, without opening any inbound port on this Comb - see docs/adr/0063-cloudflare-tunnel-exposure-v1.md in the repository. Set per-Cell on each VM's own detail page, once configured here.

{{if .CloudflareConfigured}}

configured This Comb's managerd has Cloudflare Tunnel exposure enabled.

{{else}}

not configured This Comb's managerd has no Cloudflare Tunnel exposure configured - Cells on this Comb cannot be exposed until it is.

One-time setup per Comb, done by hand (this project never automates it):

  1. The domain's DNS must already be managed by Cloudflare (its nameservers point at Cloudflare).
  2. Install cloudflared on this Comb, then run cloudflared tunnel login and cloudflared tunnel create <comb-name> once - this produces a tunnel id and a credentials JSON file.
  3. Create a Cloudflare API token scoped to Zone:DNS:Edit only (never Tunnel:Edit or account-level) for the zone Apiary will manage CNAME records in, and save it to a file only this host can read.
  4. Fill in the token file's path plus the zone/tunnel id and credentials file path below (or set the matching cloudflare_* fields directly in /usr/local/etc/apiary/managerd.json, ADR-0100), then restart apiary_managerd.

Once set, Apiary automatically creates/updates the DNS CNAME record for each exposed Cell - no manual DNS editing per Cell.
